# 第一部分 · 先把地图看清楚：技术架构梳理

## 1\.1 分层架构：一次请求的完整接力

整个博客从「你双击图标」到「页面显示」分五层接力，每一层负责一件事（配套文档有逐行版本，这里只画骨架）：

|层|代表文件|职责（大白话）|你想加功能时主要动这层吗|
|---|---|---|---|
|① 桌面壳层|`main.py`|启动 Flask 服务、开窗口、托盘、单实例——只管「把博客装进桌面」|加网页功能不用动它|
|② 路由层|`app.py` 里所有 `@app.route`|「网址分发员」：`/` 给首页、`/post/3/` 给第 3 篇文章……每个网址对应一个函数|**是**——加功能 90% 从这里开始|
|③ 数据层|`app.py` 里 `class Post/Tag/...` \+ `init_db()`|定义「文章长什么样、有哪些字段」，以及建表/补列/迁移|看情况——功能要存新数据才动|
|④ 模板层|`templates/` 下 `.html` 文件|把数据「填进」HTML 骨架，返回给浏览器|**是**——新页面必写新模板或改旧模板|
|⑤ 静态层|`static/`（tailwind/css/js）|样式、图标、前端脚本|偶尔——要新样式/新交互才动|

**一次请求的接力（以打开文章详情为例）：**浏览器请求 `/post/5/` → 路由层 `post_detail(5)` 被调用（app\.py 第1058~1059行）→ 数据层查 `Post` 表拿到文章 → 模板层 `post_detail.html` 把标题、正文、评论填进页面 → 返回 HTML。你加功能的本质就是：**加一条新路线 \+ 加一个新页面，或者改现有路线/页面的内容**。

# 第三部分 · L1 热身：两个半小时功能

## 3\.1 功能 1：文章阅读时长估算（★）

### 功能与原理

在文章详情页标题下方显示「📖 约 X 分钟读完」。原理：按中文阅读速度约 400 字/分钟估算——字数 ÷ 400 向上取整，不足 1 分钟显示「1 分钟」。这是**纯计算功能，不碰数据库**，最适合第一次动手。

### 涉及文件

|文件|改哪里|改什么|
|---|---|---|
|`app.py`|第722行附近（工具函数区）|加一个计算函数（见下）|
|`templates/post_detail.html`|标题下方|加一行显示「约 X 分钟」|

### 分步实现

**第 1 步**：在 `app.py` 的 `allowed_avatar` 函数（第722行）后面，新加一个纯函数：

```
def reading_minutes(content):
    """估算阅读时长：按 400 字/分钟，不足 1 分钟按 1 分钟算"""
    if not content:
        return 1
    total = len(content)                # 字符串长度 ≈ 字符数（含标点）
    minutes = total // 400 + (1 if total % 400 else 0)   # 除 400 有余数就 +1（向上取整）
    return max(minutes, 1)              # 至少 1 分钟，避免显示「0 分钟」

```

**为什么这么写：**① `len(content)` 统计字符数——中文博客按字符估算足够准，不需要分词这种复杂技术；② 向上取整用「整除 \+ 余数判断」而不是 `math.ceil`，少一个 import；③ 这个函数是**纯函数**（同样的输入永远同样的输出，不碰数据库不碰全局变量）——纯函数最好测、最安全，是你以后写代码的目标形态。

**第 2 步**：把函数注册成模板过滤器，这样模板里可以直接写 `{{ post.content | reading_minutes }}`（管道符号 `|` 左边是输入、右边是过滤器，这是 Jinja2 模板引擎的语法）。在刚加的函数下面补一行：

```
app.jinja_env.filters['reading_minutes'] = reading_minutes
# 注册后，模板里 {{ 'xxx' | reading_minutes }} 等价于 reading_minutes('xxx')

```

**第 3 步**：打开 `templates/post_detail.html`，找到文章标题 `<h1>` 标签附近，加一行：

```
&lt;p class="text-sm text-gray-400"&gt;📖 约 {{ post.content | reading_minutes }} 分钟读完&lt;/p&gt;

```

### 验证

重启博客 → 打开任意一篇文章详情页 → 标题下方出现「约 X 分钟读完」；字数多的文章数字更大。拿一篇已知约 2000 字的文章验证应显示「5 分钟」。

### 兼容性注意

零风险：只加了一个纯函数和一行显示，不碰数据库、不碰路由、不碰其他模板。**唯一要注意的是 ****`app.jinja_env.filters`**** 那行必须放在 ****`app`**** 对象定义之后**（放在工具函数区没问题，因为这里已经在 app 定义之后）。

**扩展知识点 · 模板过滤器：**过滤器 = 一个「吃一个值、吐一个值」的函数。Jinja2 内置了 `length`、`upper` 等过滤器，自定义过滤器就是「写函数 \+ 注册」。以后你想在模板里做任何「显示前的加工」（格式化日期、截断文字），都用这个套路。

## 3\.2 功能 2：「随机看看」按钮（★）

### 功能与原理

首页加一个「随机看看」按钮：点一下跳到一篇随机文章。原理：SQL 里用 `ORDER BY RANDOM()` 让数据库随机排序，取第一条。这是你第一次写「带查询的路由增强」。

### 涉及文件

|文件|改哪里|改什么|
|---|---|---|
|`app.py`|第1014行 `index()` 函数内|查询里加随机取一篇（见下）|
|`templates/base.html` 或 `templates/index.html`|导航栏 / 首页顶部|加「随机看看」链接|

### 分步实现

**第 1 步**：在 `index()`（app\.py 第1014行）函数体里，找到它 return 之前的查询部分，加一段「随机文章」查询。你可以把随机文章作为变量传给模板：

```
# 在 index() 里，return render_template 之前加：
random_post = Post.query.filter_by(published=True, is_deleted=False) \
                        .order_by(db.func.random()).first()
# order_by(db.func.random())：让数据库随机打乱顺序（SQLite 原生支持）
# .first()：只取第一行 → 就是"随机的一篇文章"
# filter_by(published=True, is_deleted=False)：只从已发布且未删除的文章里抽

```

然后把 `random_post` 加进 `render_template` 的参数里（找到 `return render_template('index.html', ...)`，在参数列表末尾加 `, random_post=random_post`）。

**第 2 步**：在 `templates/index.html` 顶部（或 base\.html 导航栏）加按钮，跳转到随机文章详情页：

```
{% if random_post %}
&lt;a href="{{ url_for('post_detail', post_id=random_post.id) }}"
   class="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600"&gt;
   🎲 随机看看
&lt;/a&gt;
{% endif %}

```

`{% if %}` 是模板条件：万一文章表是空的，就不显示按钮（避免死链）。`url_for('post_detail', post_id=random_post.id)` 是「反向生成网址」——按路由函数名和参数拼出 `/post/7/`，这是 Flask 的标准做法（比手写网址安全，路由路径改了它自动跟着改）。

### 验证

重启 → 首页出现「随机看看」按钮 → 连点 5 次，每次跳转的文章大概率不同（文章少于 2 篇时可能重复，属正常）。

### 兼容性注意

低风险。注意点：① `random_post` 一定要加进 `render_template` 参数，否则模板里 `random_post` 是未定义变量（Jinja2 会把未定义变量渲染成空字符串，页面不报错但按钮消失）；② 数据量大时 `func.random()` 会全表扫描，本博客个人使用文章量级完全无感。

**扩展知识点 · render\_template 传参：**路由函数里算出的每个变量，想给模板用，必须写在 `render_template('xx.html', 变量名=值)` 里。这个「路由造数据 → 模板消费数据」的管道，是整个 Flask 开发的中心思想——后面每个功能都在重复它。

# 第四部分 · L2 进阶：两个页面级功能

## 4\.1 功能 3：热门文章排行榜（★★）

### 功能与原理

新增一个 `/popular/` 页面，按浏览量从高到低列出前 10 篇文章。浏览量数据项目里**早就有了**：`Post.view_count` 字段（app\.py 第452行），后台每 30 秒把内存计数批量写进数据库（配套文档讲过的 `_vc_flusher`）。你只是把它「展示出来」。这是你第一次**完整开发一个全新页面**：新路由 \+ 新模板 \+ 导航入口三件套。

### 涉及文件

|文件|改哪里|改什么|
|---|---|---|
|`app.py`|第1267行 `archive_index()` 附近|新增 `/popular/` 路由函数|
|`templates/`|新建 `popular.html`|排行榜页面|
|`templates/base.html`|导航栏|加「热门」入口链接|

### 分步实现

**第 1 步**：在 `archive_index()`（app\.py 第1267行）函数**后面**（注意函数之间空两行），新写一个路由：

```
@app.route('/popular/')
def popular():
    """热门文章：按浏览量倒序取前 10 篇"""
    posts = (Post.query
             .filter_by(published=True, is_deleted=False)   # 只看已发布、未删除
             .order_by(Post.view_count.desc())              # 浏览量从高到低
             .limit(10)                                     # 只取前 10 条
             .all())                                        # 执行查询，返回列表
    return render_template('popular.html', posts=posts)

```

**逐行解释：**① `@app.route('/popular/')` 是装饰器，声明「网址 `/popular/` 由下面这个函数处理」——网址末尾带斜杠是 Flask 惯例，访问不带斜杠会自动 301 跳转；② 查询链从左到右读：先过滤（filter\_by）→ 再排序（order\_by）→ 再限量（limit）→ 最后执行（all）——这是 SQLAlchemy 查询的固定节奏，**别忘了最后的 ****`.all()`**（不调用它，查询不会真正执行，返回的是「待执行对象」）；③ `.desc()` = descending 倒序，加 `db.func.random()` 那种就对应「随机」。

**第 2 步**：新建 `templates/popular.html`。最省事的办法是**复制 ****`archive_index.html`**** 改**（结构最像：都是文章列表页）。核心部分：

```
&lt;h1 class="text-2xl font-bold mb-6"&gt;🔥 热门文章&lt;/h1&gt;
&lt;ol class="space-y-4"&gt;
  {% for post in posts %}
  &lt;li class="flex items-center justify-between border-b pb-3"&gt;
    &lt;a href="{{ url_for('post_detail', post_id=post.id) }}" class="hover:text-blue-600"&gt;
      {{ post.title }}
    &lt;/a&gt;
    &lt;span class="text-sm text-gray-500"&gt;{{ post.view_count }} 次浏览&lt;/span&gt;
  &lt;/li&gt;
  {% endfor %}
&lt;/ol&gt;
{% if not posts %}
&lt;p class="text-gray-400"&gt;还没有文章上榜～&lt;/p&gt;
{% endif %}

```

`{% for %}` 是模板循环：对 `posts` 列表里的每一篇文章，渲染一次 `<li>`；`{% if not posts %}` 处理空列表（空榜不报错、显示提示）。

**第 3 步**：打开 `templates/base.html` 找导航栏（里面已有「首页/归档/标签」等链接），照着加一个：

```
&lt;a href="{{ url_for('popular') }}"&gt;热门&lt;/a&gt;

```

### 验证

重启 → 点导航「热门」→ 页面按浏览量倒序列出文章；点进文章详情再返回刷新，「浏览数」增加后排行榜顺序会变化（注意：浏览量每 30 秒才落库一次，刚点完立刻刷新可能没变化）。

### 兼容性注意

低风险。① 新路由不与任何现有路由冲突（`/popular/` 此前不存在）；② `view_count` 是既有字段，零迁移；③ 记得过滤 `is_deleted=False`——排行榜漏掉软删过滤会把「已删除」文章也列出来（7\.2 会再强调）。

## 5\.1 功能 5：文章置顶（★★★）

### 功能与原理

给文章加「置顶」开关：置顶的文章永远排在首页列表最前面。这是你第一次**给数据库加字段**——整套流程（模型加列 → 迁移补列 → 查询排序 → 后台开关）是以后所有「要存新数据」功能的标准模板，务必吃透。

### 涉及文件

|文件|改哪里|改什么|
|---|---|---|
|`app.py`|Post 模型（第437行）|加 `is_pinned` 列|
|`app.py`|`init_db()`（第2248行）|加 ALTER 补列|
|`app.py`|`index()`（第1014行）|查询排序加置顶优先|
|`templates/admin/`|文章编辑页（`post_new`/`post_edit` 对应模板）|加「置顶」勾选框|

### 分步实现

**第 1 步：模型加列。**在 `Post` 类里 `published` 字段（第451行）下面加一行：

```
is_pinned = db.Column(db.Boolean, default=False)   # 置顶标记：True=排最前

```

**第 2 步：迁移补列（关键！）。**打开 `init_db()`（第2248行），找到里面已有的「ALTER 补列」代码段（配套文档讲过：用 try/except 捕获「列已存在」报错，幂等补列）。照抄那个模式，加一段：

```
# 新增：文章置顶字段（旧库自动补列，重复执行不报错）
try:
    db.session.execute(db.text('ALTER TABLE post ADD COLUMN is_pinned BOOLEAN DEFAULT 0'))
    db.session.commit()
except Exception:
    db.session.rollback()   # 列已存在会报错 → 回滚，当作"已经加过了"

```

**为什么必须走 ALTER 而不是删库重建：**你的 `blog.db` 里已有文章、评论、点赞数据，删库重建数据全没了。ALTER TABLE 只加一列、不动旧数据；「先试执行、报错就回滚」让脚本幂等——启动 100 次也只会成功补一次列。

**第 3 步：首页排序。**找到 `index()`（第1014行）里首页文章的查询，在 `order_by` 处让置顶排最前。先看现有排序，再改成：

```
# 现有排序类似：.order_by(Post.created_at.desc())
# 改成：
.order_by(Post.is_pinned.desc(), Post.created_at.desc())
# 第一个排序键 is_pinned.desc()：True(1) 排在 False(0) 前面 → 置顶优先
# 第二个排序键 created_at.desc()：置顶内部按发布时间倒序；非置顶也按发布时间倒序

```

多条件排序 = 先按第一个条件分大组，组内再按第二个条件排——SQL 的标准行为，不要写成两个查询。

**第 4 步：后台勾选框。**找到后台新建/编辑文章页面对应的模板（`templates/admin/` 下，表单里有「发布」勾选框的位置），照着加：

```
&lt;label class="flex items-center gap-2"&gt;
  &lt;input type="checkbox" name="is_pinned" {% if post and post.is_pinned %}checked{% endif %}&gt;
  置顶此文章
&lt;/label&gt;

```

然后在 `post_new()` / `post_edit()` 保存文章的地方（配套文档有逐行讲解的保存逻辑），加一行读取勾选值：

```
post.is_pinned = bool(request.form.get('is_pinned'))   # 勾了=True，没勾=False

```

### 验证

重启 → 后台编辑一篇文章勾选「置顶」→ 保存 → 回前台首页，该文排到最前；再取消置顶，恢复原顺序。重点验证：旧数据库升级后不报错（ALTER 幂等）、未勾选的文章不受影响。

### 兼容性注意

**中等风险，这里是最容易踩坑的地方：**① **Gitee 双向同步**：同步引擎（sync\_engine\.py）按「字段级游标」比对——新增列不影响旧数据同步，但**千万不要删列或改列名**，否则远端记录对不上（详见 7\.2）；② `post_new`（新建）时 `post.is_pinned = ...` 那行也要加（两个路由各加一次），漏了新建的文章永远不置顶；③ 置顶只影响首页列表，归档页/标签页的排序逻辑在别的路由里，若想让置顶全站生效，需要把第 3 步的排序应用到每个列表查询——建议先只改首页。

**扩展知识点 · 数据库迁移（初学者版）：**「迁移」= 数据库结构变了，旧数据要平滑过渡。本项目的迁移策略是「启动时自动补列」（init\_db 里跑 ALTER，幂等）。这个模式对个人项目够用；将来项目变大可以学 Alembic（Flask\-Migrate），但现在不要引入——那是下一个量级的复杂度。

## 5\.2 功能 6：RSS 订阅（★★★）

### 功能与原理

给博客加 `/feed/` 地址，输出 RSS 2\.0 格式的 XML，让阅读器（如 Inoreader、微信读书）能订阅你的文章更新。RSS 就是一个「规定好了标签怎么写的 XML 文件」，用 Python **标准库** `xml.etree.ElementTree` 就能生成——**零新依赖**，这是它入选的原因。

### 涉及文件

|文件|改哪里|改什么|
|---|---|---|
|`app.py`|第1267行附近|新增 `/feed/` 路由|
|`templates/base.html`|导航栏或 head|加订阅链接（可选）|

### 分步实现

**第 1 步**：在 app\.py 顶部 import 区（找到 `from flask import ...` 那一带）加标准库导入：

```
import xml.etree.ElementTree as ET   # 生成/解析 XML 的标准库（自带，无需安装）

```

**第 2 步**：在 `archive_index()`（第1267行）后面加路由：

```
@app.route('/feed/')
def feed():
    """RSS 2.0 订阅源：输出最近 20 篇已发布文章"""
    posts = (Post.query
             .filter_by(published=True, is_deleted=False)
             .order_by(Post.created_at.desc())
             .limit(20)
             .all())
    rss = ET.Element('rss', {'version': '2.0'})     # 根元素 rss
    channel = ET.SubElement(rss, 'channel')         # RSS 必须的 channel
    ET.SubElement(channel, 'title').text = '个人博客'             # 订阅源标题
    ET.SubElement(channel, 'link').text = 'http://127.0.0.1:5000/'  # 站点地址
    ET.SubElement(channel, 'description').text = '我的个人博客'    # 描述
    for p in posts:                                 # 每篇文章一个 <item>
        item = ET.SubElement(channel, 'item')
        ET.SubElement(item, 'title').text = p.title
        ET.SubElement(item, 'link').text = url_for('post_detail',
                                                   post_id=p.id, _external=True)
        ET.SubElement(item, 'description').text = render_markdown(p.content)[:500]
        ET.SubElement(item, 'pubDate').text = p.created_at.strftime('%a, %d %b %Y %H:%M:%S GMT')
    body = ET.tostring(rss, encoding='unicode')     # 树 → 字符串
    return app.response_class(body, mimetype='application/rss+xml')   # 以 XML 类型返回

```

**逐行解释：**① `ET.Element` 建元素、`ET.SubElement(父, 名字)` 加子元素、`.text` 赋值——这就是 XML 的「父子树」模型；② `url_for(..., _external=True)` 生成**带域名的完整网址**（RSS 阅读器在别处解析，不能用相对路径 `/post/3/`）；③ `render_markdown` 是项目现成的 Markdown 渲染函数，直接把正文渲染成 HTML 塞进 description；④ `pubDate` 必须用 RFC 822 格式（周几, 日 月 年 时:分:秒 GMT）——RSS 规范要求，阅读器靠它排序。

**第 3 步（可选）**：在 base\.html 的 `<head>` 里加订阅发现链接（让阅读器自动发现）：

```
&lt;link rel="alternate" type="application/rss+xml" title="RSS" href="{{ url_for('feed') }}"&gt;

```

### 验证

重启 → 浏览器打开 `http://127.0.0.1:5000/feed/` → 页面显示 XML（不是乱码、不是报错）；用任意 RSS 阅读器添加该地址，能看到文章列表；发布新文章后刷新订阅，新文章出现。

### 兼容性注意

低\-中风险。① `/feed/` 是新地址，不冲突；② `_external=True` 生成的域名是 `http://127.0.0.1:5000/`——本机阅读没问题，将来部署到公网需要把域名改成真实地址（把站点地址做成可配置项，参考 config\.py 的环境变量模式）；③ description 截断 500 字符避免订阅源过大；④ 同步引擎不碰这个功能，零冲突。

**扩展知识点 · ElementTree：**它是 Python 自带的最小 XML 库。「树」模型：一个根元素长出一串子元素，就像文件夹套文件夹。生成 XML 的三板斧：`Element`（建根）→ `SubElement`（挂孩子）→ `tostring`（输出字符串）。不装任何第三方库就能做 RSS/sitemap/配置文件导出。

## 6\.1 功能 7：搜索支持 tag: 标签筛选（★★★★）

### 功能与原理

现在首页搜索框只搜关键词（标题/正文/摘要，配套文档讲过 `db.or_` \+ `ilike` 的模糊查询）。本功能让搜索支持 `tag:Python` 语法：输入 `tag:Python 教程` 时，结果限定在带「Python」标签的文章里，再按关键词过滤。这是「复杂查询组合」的实战——你第一次把**多对多关联**（文章\-标签）用进查询。

### 涉及文件

|文件|改哪里|改什么|
|---|---|---|
|`app.py`|`index()`（第1014行）搜索逻辑|解析 tag: 前缀 \+ 关联过滤|
|`templates/index.html`|搜索框区域|加提示文案（可选）|

### 分步实现

**第 1 步：读懂现有搜索。**先找到 `index()` 里现有的搜索查询（配套文档标注过：用 `db.or_(Post.title.ilike(...), Post.content.ilike(...), Post.summary.ilike(...))`）。它的结构是「关键词 → 拼一个 or 条件」。我们在这个基础上加标签分支。

**第 2 步：解析 tag: 前缀。**在搜索逻辑**前面**加解析代码：

```
q = (request.args.get('q') or '').strip()    # 原始搜索词
tag_name = None
keyword = q
m = re.match(r'^tag:(\S+)\s*(.*)$', q)        # 匹配 "tag:Python 教程" 这种开头
if m:
    tag_name = m.group(1)                     # 组1 = 标签名（Python）
    keyword = m.group(2)                      # 组2 = 剩余关键词（教程，可为空）
# re.match：从头匹配；\S+ 一个或多个非空白字符；\s* 零个或多个空白；(.*) 剩余全部

```

`re.match` 的三个组：`tag:` 是字面前缀，`(\S+)` 抓标签名，`(.*)` 抓后面剩余的关键词——这就是「解析小语法」的最简形态，以后你想做 `date:2025`、`author:xx` 都照这个模板。

**第 3 步：改查询。**把现有搜索查询改成「有标签先按标签过滤，再叠加关键词」：

```
query = Post.query.filter(Post.published.is_(True), Post.is_deleted.is_(False))
if tag_name:
    # 有关联表 join 的过滤：只保留"带这个标签"的文章
    query = query.join(Post.tags).filter(Tag.slug == Tag.slugify(tag_name))
    # Post.tags 是模型里的关系名（app.py 第456行），join 后可直接用 Tag 的列过滤
if keyword:
    like = f'%{keyword}%'                    # 模糊匹配通配符
    query = query.filter(db.or_(
        Post.title.ilike(like),
        Post.content.ilike(like),
        Post.summary.ilike(like),
    ))
posts = query.order_by(Post.created_at.desc()).all()

```

**逐行解释：**① `query.join(Post.tags)` 是 SQLAlchemy 的「连表」——通过关联表把文章和标签拼成一张临时大表，之后就能用 `Tag.slug == ...` 过滤；② 标签用 `Tag.slugify(tag_name)` 转成 slug 再比（配套文档讲过 slug 是标签的唯一键，大小写都统一成小写）；③ 两个 `if` 是「可选叠加」——只给 tag: 就按标签筛、只给关键词就按词搜、两个都给就同时满足（AND）；④ **filter vs filter\_by**：filter\_by 只能写「等值」且不用写模型名，filter 能用 `==`、`.is_()`、`db.or_` 等复杂条件——这里混用，是因为 `is_(True)` 处理布尔值更严谨（SQL 里 True 不能直接 ==）。

**第 4 步（可选）**：在搜索框 placeholder 加提示：`placeholder="搜索…（支持 tag:标签名）"`。

### 验证

重启 → 首页搜索 `tag:Python` → 只显示带 Python 标签的文章；搜索 `tag:Python 教程` → 显示带 Python 标签且正文含「教程」的文章；普通关键词搜索行为与原来完全一致（回归验证）。

### 兼容性注意

**中\-高风险，务必回归验证：**① 这是**修改现有路由**，不是新增——改完必须确认普通搜索没被改坏（回归测试的典型场景：老功能行为必须不变）；② `join` 会产生重复行吗？不会——每篇带某标签的文章只 join 出一行（因为 post\_tags 里 \(post\_id, tag\_id\) 唯一）；但如果你 join 了多对多又 join 评论，就可能出现一行变多行，新手常踩，解决办法是 `.distinct()`；③ 空关键词 \+ 空标签时查询退化为「全部已发布文章」，和原来的首页行为一致，不会出问题。

**扩展知识点 · 连表（join）的直觉：**把「文章表」和「标签表」通过中间的关联表拼成一张大表，大表每行 = 「一篇文章 \+ 它身上的某个标签」。之后过滤、排序、取数都在大表上进行。多对多查询三板斧：`join(关系名)` → `filter(对方表的条件)` → 需要时 `.distinct()`。

## 6\.2 功能 8：友链申请 \+ 后台审核（★★★★）

|文件|改哪里|改什么|

### 兼容性注意

**高风险点：**① **迁移顺序**：必须先在模型加列 \+ init\_db 补列成功，再改查询——如果先改查询（status 条件）而旧库没有 status 列，所有友链查询直接报错（no such column）；② **旧数据默认值**：ALTER 加列时 `DEFAULT 'active'` 会把已有友链全部置为 active（已展示的继续展示），这是期望行为——如果你忘写 DEFAULT，旧行 status 为 NULL，前台 `status='active'` 过滤会把它们全部隐藏！③ Gitee 同步：FriendLink 若参与同步（看同步引擎的模型清单），status 作为新列同样要「只加不改」；④ 后台链接页若原来循环不加 status 判断，现在要区分显示「待审核」徽标。

# 项目整体介绍

## 这个博客能做什么

简单说，这是一个「自己写的 WordPress」。它把一个博客网站常见的功能都实现了：

- **文章管理**：发布、编辑、删除文章，支持 Markdown 语法（一种用简单符号写格式的纯文本写法，比如用 `#` 表示标题、用 `**文字**` 表示加粗）

- **标签分类**：给文章打标签，按标签筛选文章

- **评论与回复**：访客可以评论，还能回复别人的评论（一级嵌套）

- **点赞**：每个访客按「IP \+ 浏览器信息」生成一个指纹，同一个人只能点一次

- **搜索**：按标题/正文/摘要搜索，命中关键词会在结果里高亮显示

- **归档、关于、友链**：按月份归档、个人介绍页、友情链接管理

- **后台管理**：发文章、传文件导入、改资料、管友链，都有现成页面

- **个性化**：头像裁剪、背景图、7 套主题切换

- **桌面版**：除了网页版，还能打包成一个 Windows 桌面程序（带系统托盘），这是 `main.py` 干的事

- **云端同步（Gitee）**：可以把博客数据同步到 Gitee（一个代码托管网站）私有仓库，多台电脑间双向同步。**v2.1 起「备份/恢复」已并入同步**——点「备份」= 推送到 Gitee，点「恢复」= 从 Gitee 拉回，并内置「零门槛 · 新手向导」带你 4 步连上 Gitee

## 技术栈：每个词都讲人话

整个项目用到的核心技术，用表格列出来，每个名词后面是「人话解释」：

|名词|在项目里的角色|大白话解释|
|---|---|---|
|Python|编程语言|我们写代码用的语言，项目所有逻辑都是它写的|
|Flask|Web 框架|一个「帮你处理网站请求」的工具箱。浏览器访问网址，Flask 负责接住请求、执行对应代码、把网页返回给浏览器|
|Flask\-SQLAlchemy|数据库工具（ORM）|ORM 的意思是「用 Python 代码操作数据库，不用手写 SQL 语句」。比如「存一篇文章」就是 `db.session.add(文章)` 一句代码|
|SQLite|数据库|一个「把数据存成单个文件」的小型数据库。项目所有数据都存在 `blog.db` 这个文件里，不需要安装数据库软件|
|Jinja2|模板引擎|把「网页骨架（HTML）\+ 动态数据」拼成最终网页的工具。HTML 是描述网页长什么样的标记语言|
|Tailwind|CSS 框架|CSS 是控制网页「好不好看」的语言。Tailwind 是别人写好的一套样式工具，让我们不用自己写大量 CSS|
|Vditor|前端编辑器|网页上的 Markdown 编辑器，写文章时用的输入框|
|pywebview|桌面壳|把网页「装进一个 Windows 窗口」的库。桌面版就是用浏览器内核（WebView2）渲染网页，看起来像个独立软件|
|waitress|WSGI 服务器|WSGI 是 Python 网页应用与服务器之间的接口标准。waitress 是一个稳定的服务器程序，负责真正接收网络请求并转给 Flask|
|PyInstaller|打包工具|把 Python 项目打包成 `个人博客.exe`，让没有装 Python 的电脑也能直接双击运行|

## 两种运行形态：网页版与桌面版

这个项目可以用两种方式运行，理解它们的区别，后面调试才不会懵：

|对比项|网页服务版（app\.py）|桌面版（main\.py）|
|---|---|---|
|启动命令|`python app.py`|`python main.py`|
|打开方式|浏览器访问 `http://127.0.0.1:5000`|弹出独立 Windows 窗口（内部用 WebView2 渲染同一个网页）|
|端口|5000（config\.py 里的 PORT）|18520（main\.py 里固定首选）|
|适用场景|局域网手机访问、当作真正的网站部署|自己日常使用，像装了个软件|
|附加功能|无|单实例防重复、系统托盘、窗口图标|

**重要概念：127\.0\.0\.1 是什么？**它叫「本机回环地址」，意思是「只在这台电脑内部访问自己」，外网和其他设备访问不到。后面你看到 `127.0.0.1:5000` 就理解成「这台电脑的 5000 号端口」即可。**端口**可以理解成电脑上给程序用的「门牌号」，一个程序占用一个门牌号，别人通过这个门牌号找到它。

## 一次访问发生了什么：数据流向

先建立整体心智模型。当你在浏览器里打开博客首页时，背后发生了这样一串事（对照着 `app.py` 的代码理解）：

1. 浏览器向 `http://127.0.0.1:5000/` 发了一个「请求」：给我首页

2. 服务器（waitress 或 Flask 内置服务器）接住请求

3. Flask 看请求的网址（路径 `/`），去「路由表」里找到对应函数——这里是 `index()`（首页函数）

4. `index()` 从数据库里查出「已发布的文章列表」

5. 把文章数据交给 `index.html` 模板，模板把数据「填」进 HTML 骨架，生成完整的网页代码

6. Flask 把这个网页代码作为「响应」返回给浏览器

7. 浏览器把 HTML 渲染成你看到的漂亮页面

这个「网址 → 函数」的对应关系，就是 Flask 里的**路由（route）**，是理解整个项目的一把钥匙。第 3 章我们逐行看代码时，你会反复见到 `@app.route(...)` 这行魔法注释——它就是在「登记路由」。

# 环境搭建手把手

本章目标：让代码在你电脑上能跑起来。我们会依次完成「装 Python → 验证 → 建项目文件夹 → 建虚拟环境 → 装依赖 → 认识配置文件」。每一步都给了命令、执行位置和「成功长什么样」。

## 第 1 步：安装 Python

**为什么要装？**项目是 Python 写的，电脑上得有 Python 解释器（可以理解成「翻译官」，把 Python 代码翻译成电脑能执行的指令）才能运行。

**操作：**

1. 打开浏览器，访问 Python 官网：`https://www.python.org/downloads/`

2. 点黄色大按钮 `Download Python 3.11.x`（本项目在 3\.11 上开发，3\.10\~3\.12 都兼容。不建议下 3\.13 以上，个别库可能还没适配）

3. 下载完成后双击安装包

4. **关键一步**：安装界面第一页最下方有个勾选框 `Add python.exe to PATH`，**必须打勾**。PATH 是 Windows 的环境变量列表，勾上之后，你在命令行敲 `python` 才能找到它。不打勾，后面每一步都会报「python 不是内部或外部命令」

5. 点 `Install Now`（默认安装），等待完成

如果你电脑上已经装过 Python，先别急着卸载。打开「命令提示符」（按 Win 键，输入 cmd，回车），敲 `python --version`，如果显示 3\.10\~3\.12 就可以直接用，跳到第 2 步验证。

## 第 2 步：验证 Python 装好了

**执行位置：**任意文件夹都可以（打开命令提示符 cmd 即可）。

**命令与期望输出：**

```powershell
python --version
# 期望输出类似：Python 3.11.7

pip --version
# 期望输出类似：pip 23.x from ... (python 3.11)
```

**为什么有两个命令？**`python` 是解释器本身；`pip` 是 Python 自带的「软件商店」，专门用来下载安装别人写好的库（比如 Flask）。后面所有第三方库都靠它装。

如果提示「python 不是内部或外部命令」：多半是刚才没勾 PATH。两个解法：① 重装一遍 Python，这次记得勾 PATH；② 不重装，在搜索框搜「编辑系统环境变量」，把 Python 安装目录（如 `C:\Users\你的用户名\AppData\Local\Programs\Python\Python311` 和它的 `Scripts` 子目录）加进 Path 变量。重装更省事。

## 第 3 步：建项目文件夹并放入代码

**操作：**在 D 盘（或你喜欢的位置）新建文件夹，命名 `blog`。把项目里的所有文件和文件夹（`app.py`、`main.py`、`config.py`、`templates`、`static`、`requirements.txt` 等）复制进去。

**路径别用中文！**比如别放在 `D:\我的博客\`。原因：部分 Python 库和打包工具处理中文路径会报编码错误（本项目实测遇到过）。统一用英文路径最省心。后面所有命令的「执行位置」默认都是 `D:\blog`，我会反复写，请以它为准。

## 第 4 步：创建虚拟环境（venv）

**为什么需要虚拟环境？**每个项目用的库版本可能不一样。如果不隔离，项目 A 升级了 Flask，可能把项目 B 弄崩。虚拟环境就是给每个项目一个「独立的库房间」，互不干扰。这是 Python 项目开发的标准做法。

**执行位置：**`D:\blog`（在 cmd 里先敲 `cd /d D:\blog` 进入，`cd` 是 change directory 切换目录的意思，`/d` 是告诉 cmd 连盘符一起切）

```powershell
python -m venv .venv
# -m 表示"用 python 这个程序去运行 venv 模块"
# .venv 是虚拟环境文件夹的名字（前面带点，表示是隐藏配置类目录）
# 命令执行完没有任何输出 = 成功；D:\blog 下会出现一个 .venv 文件夹
```

## 第 5 步：激活虚拟环境

**为什么要激活？**激活之后，你在命令行敲的 `python`、`pip` 才会指向虚拟环境里的那套，装的库才会进虚拟环境的「房间」。

**执行位置：**`D:\blog`

```powershell
.venv\Scripts\activate
# 激活成功后，命令行最左边会多出 (.venv) 字样，像这样：
# (.venv) D:\blog>
```

激活后命令行出现 `(.venv)` 前缀，就是成功标志。以后每次新开命令行窗口，都要先执行这一步激活，再执行别的命令。如果用的是 VS Code 终端或 PyCharm 终端，它们可能自动激活。

## 第 6 步：安装项目依赖

**为什么用 requirements\.txt？**一个项目可能依赖几十个第三方库。把它们写进这个清单文件，一条命令就能全部装好，别人拿到项目也能一键复现环境。

**执行位置：**`D:\blog`（确认命令行开头有 `(.venv)`）

```powershell
pip install -r requirements.txt
# -r 是 requirements 的缩写，意思是"按这个文件里列的清单安装"
# 会看到一堆 "Downloading... Installing..." 输出，最后出现 Successfully installed ... 即成功
```

**每个依赖是干什么的：**

|依赖包|作用|
|---|---|
|Flask\>=3\.0\.0|Web 框架，处理网址路由和请求|
|Flask\-SQLAlchemy\>=3\.1\.1|操作数据库的 ORM 工具|
|Werkzeug\>=3\.0\.0|Flask 的底层工具库（安全文件名处理、密码等），Flask 自动依赖它|

## 第 7 步：认识配置文件与关键配置项

安装完成后先别急着运行。先花 5 分钟认识 `config.py`——它管理着「项目跑在哪个端口、数据存哪、密钥是什么」等全局设定。配置文件的原则是：**凡是可能要改的值，都集中放这里，而不是散落在代码里**。

**怎么打开看：**用记事本或 VS Code 打开 `D:\blog\config.py`。

**关键配置项对照表（改完保存即可，重启程序生效）：**

|配置项|默认值|怎么填 / 什么含义|
|---|---|---|
|`DATA_DIR`|exe 所在目录（源码运行时就是项目根目录）|可写数据的家：数据库、上传文件、日志都在它下面。一般不用改|
|`RESOURCE_DIR`|源码目录（打包后是只读解压目录）|只读资源（templates/static）的位置。一般不用改|
|`SECRET_KEY`|自动生成并存到 `.session_key` 文件|给登录会话 cookie 签名的密钥。项目已自动持久化，你不需要填。⚠️ 不要泄露给别人|

### 开头：路径与打包兼容


- `os.path.dirname(__file__)`：拿到「当前文件（config\.py）所在文件夹」。`__file__` 是 Python 内置变量，代表当前文件路径。`abspath` 把它转成绝对路径（带完整盘符）。所以 `BASE_DIR` 就是项目根目录

- `getattr(sys, 'frozen', False)`：判断程序是不是「被打包成 exe 后运行的」。`frozen` 是 PyInstaller 打包后注入的特殊标志；如果为真，说明我们在跑打包版

- 打包版为什么路径不同？PyInstaller 会把 `templates`、`static` 等只读资源解压到一个临时只读目录 `sys._MEIPASS`；而数据库、上传文件必须放在可写的 exe 旁边（`sys.executable` 是 exe 文件的路径）。所以打包版要「资源」和「数据」分开——这个设计解决了打包后没法写文件的大坑

### SECRET\_KEY：会话密钥的持久化

```python
def _ensure_persistent_secret_key(data_dir: str) -> str:
    key_env = os.environ.get('SECRET_KEY')
    if key_env:
        return key_env
    os.makedirs(data_dir, exist_ok=True)
    path = os.path.join(data_dir, '.session_key')
    if os.path.isfile(path):
        content = open(path, 'r', encoding='utf-8').read().strip()
        if len(content) >= 32:
            return content
    import secrets
    new_key = secrets.token_hex(48)
    ...  # 写回磁盘
    return new_key
```

- **会话（session）是什么？**网页记不记得「你登录过」，靠一个叫 cookie 的小纸条。Flask 用 SECRET\_KEY 给这个小纸条「盖章」防伪造。密钥每次变，旧纸条就失效——表现为「重启就要重新登录」

- 这段代码干的事：优先读环境变量 `SECRET_KEY`；没有就用随机数生成一个 96 位十六进制密钥，存进 `.session_key` 文件。下次启动读同一文件，密钥不变 → 登录状态跨重启保持。这是项目「不用每次重登」的实现细节

- v1\.3 起登录功能已移除，这个机制保留是为了兼容（不再有实际登录动作）

### Post 模型逐行看

```python
class Post(db.Model):
    __tablename__ = 'post'

    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    content = db.Column(db.Text, nullable=False)
    summary = db.Column(db.String(500))
    published = db.Column(db.Boolean, default=True)
    view_count = db.Column(db.Integer, default=0)
    rendered_html = db.Column(db.Text)
    created_at = db.Column(db.DateTime, default=datetime.datetime.utcnow)
    updated_at = db.Column(db.DateTime, default=datetime.datetime.utcnow,
                            onupdate=datetime.datetime.utcnow)

    tags = db.relationship('Tag', secondary='post_tags',
                           backref=db.backref('posts', lazy='dynamic'))
```

- `class Post(db.Model)`：定义模型类。`db.Model` 是 SQLAlchemy 的「模型基类」，继承了它，这个类就和一张表绑定

- `db.Column(类型, 约束)`：定义一列。`db.Integer` 整数、`db.String(200)` 最长 200 字符的文本、`db.Text` 长文本、`db.Boolean` 真假值、`db.DateTime` 时间

- `primary_key=True`：主键，每行数据的唯一编号（自动递增）。`nullable=False`：这一列不能为空（不填就报错）

- `default=...`：不填时自动用这个值。`onupdate`：每次更新自动改时间——所以 `updated_at` 永远记录「最近一次修改时间」

- `db.relationship('Tag', secondary='post_tags')`：文章和标签是「多对多」关系（一篇文章多个标签，一个标签多篇文章），`post_tags` 是它们之间的中间表。这行代码让我们能写 `post.tags.append(tag)` 直接操作标签，不用管中间表细节

### render\_markdown：Markdown 转 HTML

```python
def render_markdown(text):
    """Markdown -> HTML，带目录、代码高亮、表格等"""
    extensions = [
        FencedCodeExtension(), 'tables', 'sane_lists',
        TocExtension(permalink=True, toc_depth='2-4'),
```

- 作用：把用户写的 Markdown 纯文本（如 `# 标题`、`**加粗**`）转换成浏览器认识的 HTML 标签（`<h1>`、`<strong>`）

- `extensions` 是开启的增强插件：`FencedCodeExtension` 支持 \`\`\` 围栏代码块；`'tables'` 支持 Markdown 表格；`codehilite` 代码高亮；`nl2br` 把换行自动转成 `<br/>`

### generate\_summary：自动摘要

```python
def generate_summary(content, length=180):
    text = re.sub(r'```.*?```', '', content, flags=re.S)   # 去掉代码块
    text = re.sub(r'[#*_`>\-\[\]!()]', '', text)          # 去掉Markdown符号
    text = re.sub(r'\s+', ' ', text).strip()               # 压缩空白
    if len(text) > length:
        text = text[:length] + '...'
    return text
```

- `re.sub(规则, 替换成, 文本)`：正则表达式替换。正则是一种「用符号描述文字规律」的匹配语言，比如 `r'```.*?```'` 表示「两个 \`\`\` 之间的所有内容」

- 三步走：删掉代码块 → 删掉 Markdown 的格式符号 → 把连续空白缩成一个空格。最后截前 180 字当摘要。这就是首页卡片上那段灰色小字的来历

### parse\_front\_matter：解析文件头部信息

```python
def parse_front_matter(text):
    if text.startswith('---'):
        match = re.match(r'^---\s*\n(.*?)\n---\s*\n?(.*)', text, flags=re.S)
        if match:
            try:
                meta = yaml.safe_load(match.group(1)) or {}
                body = match.group(2)
                return meta, body
            except yaml.YAMLError:
                pass
    return {}, text
```

- **front\-matter 是什么？**Markdown 文件最开头用 `---` 包起来的一段 YAML，用来写「这篇文件的元信息」（标题、日期、标签）。这是从 Gitee 批量导入文章时的标准格式，`uploads/sample_post.md` 里有现成例子

- 正则 `^---\s*\n(.*?)\n---` 匹配两个 `---` 之间的内容；`yaml.safe_load` 把这段 YAML 文本解析成 Python 字典（键值对）。返回 `(meta, body)`：头部信息和正文分开

### like\_fingerprint：访客指纹

```python
def like_fingerprint():
    import hashlib
    ip = request.headers.get('X-Forwarded-For', request.remote_addr or 'anon')
    ua = request.headers.get('User-Agent', '')
    return hashlib.sha256(f'{ip}|{ua}'.encode('utf-8')).hexdigest()
```

- `request.headers.get(...)`：读取浏览器请求里带的头部信息。IP 是谁、浏览器是什么，都在里面

- `hashlib.sha256(...)`：把「IP\|浏览器」拼成字符串，算出一个 64 位十六进制指纹。同一台设备指纹相同，不同设备几乎不可能撞车——这就是「一个人只能点一次赞」的实现

路由（route）就是「网址 → 函数」的登记表。下面挑 6 个最核心的路由，它们覆盖了「读文章、写评论、点赞、后台管理、删文章」的完整链路。

### 路由 1：首页 index

```python
@app.route('/')
def index():
    """首页：文章列表"""
    page = request.args.get('page', 1, type=int)
    query = request.args.get('q', '').strip()
    category = request.args.get('category', '').strip()

    q = Post.query.filter_by(published=True)
    if query:
        q = q.filter(db.or_(
            Post.title.ilike(f'%{query}%'),
            Post.content.ilike(f'%{query}%'),
            Post.summary.ilike(f'%{query}%')
        ))
    pagination = q.order_by(Post.created_at.desc()).paginate(
        page=page, per_page=app.config['POSTS_PER_PAGE'], error_out=False
    )
    return render_template('index.html',
                           posts=pagination.items,
                           pagination=pagination,
                           query=query)
```

- `@app.route('/')`：装饰器。把下面这个函数注册到网址 `/`（就是首页）。`@` 开头的行叫装饰器，可以理解成「给函数贴标签登记」

- `request.args.get('page', 1, type=int)`：读网址问号后的参数。`/?page=2` 里 `page=2` 就是 args。`type=int` 强制转成整数，转不了就用默认值 1

- `Post.query.filter_by(published=True)`：从文章表里筛出「已发布」的。query 是 SQLAlchemy 的查询入口，filter\_by 是按条件过滤

- `ilike(f'%{query}%')`：模糊搜索（忽略大小写）。`%词%` 表示「包含这个词」——这是 SQL 的模糊匹配写法，f\-string（`f'...'`）把变量填进字符串

- `order_by(Post.created_at.desc())`：按创建时间倒序（新的在前）。`paginate(...)`：分页，每页 `POSTS_PER_PAGE`（8）篇

- `render_template('index.html', ...)`：渲染模板。把 posts、pagination 这些数据「传」给模板文件，模板负责排版

```python
    next_post = Post.query.filter(Post.id > post.id,
                                  Post.published == True
                                  ).order_by(Post.id.asc()).first()

    all_visible = (Comment.query
                   .filter_by(post_id=post.id, is_visible=True)
                   .order_by(Comment.created_at.asc()).all())
    comment_count = len(all_visible)

    like_count = Like.query.filter_by(post_id=post.id).count()
    liked = Like.query.filter_by(
        post_id=post.id, fingerprint=like_fingerprint()
    ).first() is not None

    return render_template('post_detail.html', post=post,
                           html_content=html, prev_post=prev_post,
                           next_post=next_post, comment_count=comment_count,
                           like_count=like_count, liked=liked)
```

- `<int:post_id>`：网址里的动态参数。`/post/3/` 里的 3 会被转成整数变量 `post_id` 传给函数——这是 Flask 最常用的动态路由写法

- `get_or_404(post_id)`：按 id 查文章，查不到直接返回 404 页面（省得自己写判断）

- `abort(404)`：v1\.3 移除登录后，未发布（草稿）文章一律对外隐藏——访问直接 404

- `post.rendered_html or render_markdown(...)`：优先用缓存好的 HTML，没有才现场渲染。这是性能优化：Markdown 渲染挺费时，渲染一次存进数据库，以后直接读

- 上下篇：查「id 比当前小的最后一条」和「id 比当前大的第一条」，就是上一篇/下一篇

- 评论：一次查出这篇文章所有可见评论，`len()` 就是评论数（比一条条数快得多）

- 点赞：`count()` 数总数；再按当前访客指纹查一次，判断「我点过没」，用于页面显示红心状态

- `methods=['POST']`：这个网址只接受 POST 请求（提交表单用）。GET 是「要数据」，POST 是「提交数据」——浏览器发评论用的就是 POST

- `request.form.get(...)`：读取表单里用户填的字段（表单是网页上的输入框集合）

- `.strip()`：去掉首尾空格，防止用户输入纯空格

### 路由 4：点赞 post\_like

```python
@app.route('/post/<int:post_id>/like/', methods=['POST'])
def post_like(post_id):
    """点赞 / 取消赞"""
    fp = like_fingerprint()
    like = Like.query.filter_by(post_id=post_id,
                                fingerprint=fp).first()
    if like:
        db.session.delete(like)      # 点过 → 取消
    else:
        db.session.add(Like(post_id=post_id, fingerprint=fp))  # 没点过 → 点赞
    db.session.commit()
    return jsonify(ok=True, count=Like.query.filter_by(
        post_id=post_id).count())
```

- 先用指纹查「我点过没」：点过就删掉（取消赞），没点过就新增（点赞）——这是一个「切换」逻辑

- `jsonify(ok=True, count=...)`：返回 JSON（一种给程序读的文本格式）。前端 JS 收到后把按钮状态和数字刷新，页面不用整页刷新

```python
@app.route('/admin/post/new/', methods=['GET', 'POST'])

```

- 一个路由同时处理 GET（打开表单页）和 POST（提交表单）：`if request.method == 'POST'` 分叉——提交了就走保存逻辑，否则渲染空表单

- `[t.strip() for t in ... if t.strip()]`：列表推导式，一行写出「把逗号分隔的标签拆开、去空格、去掉空的」的循环逻辑。这是 Python 的招牌写法

- `get_or_create_tag(name)`：标签不存在就创建，存在就取出来（工具函数）

- `post.tags.append(tag)`：把标签挂到文章上（多对多关系就这么简单）

```python
@app.route('/admin/post/<int:post_id>/delete/', methods=['POST'])
@login_required
def post_delete(post_id):
    """删除文章（含评论、点赞级联清理）"""
    post = Post.query.get_or_404(post_id)

    # 顺序很重要：先删点赞 → 再删评论 → 最后删文章
    Like.query.filter_by(post_id=post.id).delete(synchronize_session=False)
    Comment.query.filter_by(post_id=post.id).delete(synchronize_session=False)
    db.session.delete(post)
    db.session.commit()
    flash('文章已删除', 'success')
    return redirect(url_for('admin_dashboard'))
```

- 这就是修复「删除文章报错」的最终实现。错误根源：评论表的 `post_id` 是 NOT NULL（不能为空）。如果直接用 ORM 级联删除，某些情况下 SQLAlchemy 会先尝试把评论的 post\_id 置空再删，直接撞上 NOT NULL 约束 → 报 `NOT NULL constraint failed: comment.post_id`

- 修复思路：**先显式删除点赞 → 再显式删除所有评论 → 最后删除文章**。顺序保证数据库里永远不会出现「评论还在、文章没了」的脏状态

- `.delete(synchronize_session=False)`：批量删除语句，False 表示不让 ORM 同步会话（性能考虑，直接发 SQL 到数据库）

## templates：模板系统怎么看

模板 = 网页骨架 \+ 数据插槽。Jinja2 用两种「魔法符号」：`{{ 变量 }}` 输出数据，`{% 语句 %}` 写逻辑（循环、判断、继承）。

### base\.html：全站骨架与继承

```html
<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}{{ site_name }}{% endblock %}</title>
    ...
</head>
<body>
    {% include 'nav.html' %}      {# 导航栏 #}
    {% block content %}{% endblock %}   {# 页面内容插槽 #}
    {% include 'footer.html' %}   {# 底部 #}
</body>
</html>
```

- `{% block 名字 %}`：定义「插槽」。子模板用同样的 block 名字填充内容

- `{% include 'nav.html' %}`：把别的模板嵌进来（导航、底部全站复用）

- 这叫「模板继承」：所有页面都继承 base\.html，公共部分只写一次

### index\.html：循环展示文章

```html
{% extends 'base.html' %}

{% block content %}

    <article>
        <h2><a href="{{ url_for('post_detail', post_id=post.id) }}">
            {{ post.title }}</a></h2>
        <p>{{ post.summary }}</p>
    </article>
{% endfor %}
{% endblock %}
```

- `{% extends 'base.html' %}`：声明「我继承 base\.html」

- `{% for post in posts %}`：循环。把后端传来的文章列表一个个渲染成卡片

- `url_for('post_detail', post_id=post.id)`：按路由函数名反推网址（比手写网址安全，路由改名会自动跟随）

`main.py`（约 1240 行）是桌面版的大脑：它负责「找端口 → 后台启动博客服务 → 打开桌面窗口 → 挂上系统托盘」。网页版用不到它，但它把项目从「网站」升级成「软件」。

### 单实例互斥：防止开两个

```python
def _acquire_single_instance() -> bool:
    """Windows 命名互斥体：保证同时只有一个博客实例在跑"""
    import ctypes
    from ctypes import wintypes
    CreateMutexW = ctypes.windll.kernel32.CreateMutexW
    handle = CreateMutexW(None, True, _MUTEX_NAME)
    if GetLastError() == ERROR_ALREADY_EXISTS:
        return False   # 已有一个实例在跑
    return True
```

- **互斥体（Mutex）是什么？**Windows 提供的「一次只能一个人用」的锁。给锁起个固定名字（`_MUTEX_NAME`），第二次启动时发现锁已被占用 → 直接退出，并让已有窗口弹到前台

- `ctypes.windll`：Python 直接调用 Windows 系统 API 的方式（Windows API 是系统提供给程序的功能接口）。桌面程序免不了用它

### 端口选择：固定 18520

```python
def _try_find_port(start=18520, end=18620) -> int:
    """找一个 127.0.0.1 上空闲的本地端口，首选固定 18520"""
    preferred = 18520
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    try:
        s.bind(('127.0.0.1', preferred))
        return preferred          # 18520 空闲，就用它
    except OSError:
        pass
    finally:
        s.close()
    for p in range(preferred + 1, end):   # 被占用则向后扫
        ...
```

- 原理：试着「占用」某个端口，占用成功说明它空闲，立刻归还并采用它

- **为什么固定 18520 而不随机？**浏览器会把不同端口的登录 cookie 分开存。端口老变 → 用户感觉「老要重新登录」。固定端口是桌面版稳定性的关键设计。默认端口在 `config.py` 是 5000，桌面版 `main.py` 首选 18520——两者不冲突

### 后台启动博客服务

```python
def _start_blog_server(port):
    """在后台线程启动 waitress，直到 shutdown 事件后关闭"""
    import waitress.server
    import app as _app_mod
    from config import Config as _Cfg

    os.makedirs(_Cfg.UPLOAD_FOLDER, exist_ok=True)
    _app_mod.init_db()   # 建表（幂等，跑多次不报错）

    server = waitress.server.create_server(
        _app_mod.app, host='127.0.0.1', port=port,
        threads=8, channel_timeout=60, connection_limit=32)
    t = threading.Thread(target=server.run, daemon=True)
    t.start()
    return t
```

- `import app as _app_mod`：把 app\.py 当模块引入（不重复启动），拿到 Flask 应用对象

- `init_db()`：确保数据库建好。注释里的「幂等」意思是「执行多次结果一样」，安全

- `waitress.server.create_server(...)`：用 waitress 起服务器（比 Flask 自带服务器稳定，适合真正运行）。`threads=8`：8 个线程同时处理请求

- `daemon=True`：后台守护线程，主程序退出它跟着退出

### 托盘：桌面右下角的小图标

```python
def _tray_wndproc(hwnd, msg, wparam, lparam):
    """托盘窗口消息处理：鼠标事件、退出命令都走这里"""
    if msg == WM_TRAYICON:          # 系统发给托盘消息窗口的自定义消息
        ev = lparam & 0xFFFF        # 低 16 位是鼠标事件类型
        if ev in (WM_LBUTTONUP, WM_LBUTTONDBLCLK):   # 左键单击/双击
            _tray_show_activate()                   # → 打开/显示主窗口
        elif ev in (WM_RBUTTONUP, WM_CONTEXTMENU):  # 右键（v4/v3 两种协议）
            _tray_show_menu()                       # → 弹出菜单
    elif msg == WM_COMMAND:         # 菜单项命令
        _tray_handle_command(wparam & 0xFFFF)
    return 0
```

- **托盘是什么？**Windows 右下角任务栏（时钟旁边）的一排小图标。程序缩小到托盘后，窗口关了程序还在后台跑，点图标又能叫出来

- `lparam & 0xFFFF`：消息参数的低 16 位是「鼠标事件类型」。判断左键（打开窗口）/ 右键（弹出菜单）。`0xFFFF` 是十六进制数，表示「取低 16 位」——这是 Windows 消息的固定格式

- 本项目托盘交互按你的要求精简为：**左键单击 = 打开/显示主窗口；右键单击 = 弹出菜单（打开博客 / 打开管理后台 / 退出博客）**；不弹通知消息

```python
def _tray_handle_command(cmd):
    if cmd == ID_TRAY_OPEN:        _tray_show_window()
    elif cmd == ID_TRAY_ADMIN:     _tray_open_admin()
    elif cmd == ID_TRAY_QUIT:      _tray_request_quit()
```

- 菜单项点下去后，Windows 会发 WM\_COMMAND 消息，参数里带「点了哪一项」的编号（ID）。每个 ID 对应一个动作：打开 / 后台 / 退出。退出会先停服务器、再关窗口、最后释放互斥锁，干净退出

- `webview.start()`：pywebview 的主循环，它一直运行，处理窗口的各类事件（最小化、托盘消息等）

## 端口被占用怎么办

# 常见踩坑排查清单

以下问题全部来自这个项目真实踩过的坑，按「症状 → 原因 → 解法」组织。排查顺序建议：先看报错最后几行 → 再看 logs/blog\.log → 再对号入座。

## 环境安装类

|症状|原因|解法|
|---|---|---|
|`'python' 不是内部或外部命令`|装 Python 时没勾 Add to PATH|重装 Python 并勾选 PATH，或手动把 Python 目录加进系统 Path|
|`pip install` 报红字网络超时|默认源在国外，网络慢|用国内镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`|
|激活虚拟环境后 `pip` 还是全局的|激活命令没执行成功或窗口没重开|确认命令行前缀有 `(.venv)`；没有就重新执行 `.venv\Scripts\activate`|
|运行报 `ModuleNotFoundError: No module named 'xxx'`|缺某个依赖没装上|执行 `pip install -r requirements.txt` 补装；项目还带 `check_env.py` 可自检|

## 运行与界面类

|症状|原因|解法|
|---|---|---|
|`Address already in use` / 页面打不开|端口被别的进程占用|netstat 查占用进程 kill 掉，或用 \.env 改 `BLOG_PORT`|
|桌面版窗口白屏|WebView2 运行时缺失，或服务没起来|装 WebView2 Runtime；或先单独跑 `python main.py` 看终端报错|
|运行报 `UnicodeEncodeError`（emoji/中文崩溃）|Windows 命令行 GBK 编码问题|项目已在顶部自动修复；若自定义脚本仍崩，检查是否用了 GBK 环境的输出|
|代码在中文路径下报错/打包失败|部分库不支持中文路径|把项目移到英文路径（如 `D:\blog`），这是本项目已知约束|
|托盘图标没出现，关窗口程序就退出|托盘线程启动失败，或窗口关闭策略没设置|确认 main\.py 里窗口关闭事件已绑定「隐藏到托盘」而非真退出；看 logs 里托盘相关报错|
|托盘左右键点了没反应|Windows 消息的 lParam 位运算/消息注册问题|确认用 `lparam & 0xFFFF` 取低 16 位比较鼠标事件；真实消息高 16 位是图标 ID，比较整值会永远不匹配——这是本项目修过两次的坑|

## 数据库类

|症状|原因|解法|
|---|---|---|
|删文章报 `NOT NULL constraint failed: comment.post_id`|评论的 post\_id 不允许为空，删除顺序不对导致先置空再删|按「先删点赞 → 再删评论 → 最后删文章」的顺序显式删除（本项目 v1\.3\.4 已修复，删除时同步清点赞与评论）|
|报 `database is locked`|SQLite 同时被多个连接写|配置里已有 `timeout=30`；避免同时开两个实例（单实例锁会拦）；也可关掉占用的程序再试|
|数据库升级后老库缺列|老库没有新版本的列|项目 init\_db\(\) 内置轻量迁移（ALTER TABLE 补列），启动即自动补齐；如手工改过库结构，先备份 blog\.db|
|改代码后页面还是旧内容|浏览器缓存或服务没重启|强制刷新（Ctrl\+F5）；开发模式确保 `FLASK_DEBUG=1` 或手动重启进程|

## 桌面版与打包类

|症状|原因|解法|
|---|---|---|
|桌面版登录态丢失、老要重登|端口漂移导致浏览器把 cookie 按端口分开存|桌面版固定首选端口 18520（main\.py 的 `_try_find_port`），只有被占用才顺延|
|双击 exe 没反应|打包缺资源或运行库|在命令行直接运行 exe 看报错；确认 spec 里打包了 templates/static；确认目标机有 WebView2|
|打包后找不到模板/静态文件|资源目录与数据目录混淆|代码必须用 `Config.RESOURCE_DIR`（打包后指向 sys\.\_MEIPASS）而非源码相对路径|
|日志里 `[博客服务] exited`|waitress 服务线程异常退出|看退出前最后几条日志定位原因；常见是端口占用或数据库文件损坏|

## 通用排查方法论

1. **先读报错最后 5 行**：错误类型和位置都在结尾，开头的大段堆栈多半是「过程」

2. **再看日志文件**：`D:\blog\logs\blog.log`，按时间倒序找最近的 `ERROR`/`WARNING`

3. **还原最小场景**：把问题缩到最小复现步骤（比如「只删一篇文章就报错」），比在完整流程里猜快得多

4. **搜索关键词**：把报错里的英文关键词（如 `NOT NULL constraint failed`）原样搜索，绝大多数坑都有人踩过

5. **改一处验证一处**：一次只改一个变量/一个顺序，改完立即跑，避免多个改动混在一起找不到凶手
